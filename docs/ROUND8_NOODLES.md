# 0.8.0 面条推荐修复

明确本餐仅偏好面条时，先检查忌口、硬约束、配送、售罄和避重，再优先推荐面条主餐；套餐可配面不能与面条主餐混为一类。当前示例按结构化的主食noodle、菜系noodles识别面条主餐，后续目录可用meal_kind显式分类；不按菜名猜测或按用户输入写固定商品返回。

没有合适的面条主餐时显示“当前没有符合要求的面条主餐”，默认不把其他餐食列为主推。用户可以查看已跳过餐食、调整要求，或主动选择“查看配面套餐和其他餐食”。替代餐继续执行全部已有忌口与硬约束；新餐或要求、上下文变化后重置本餐替代餐选择。

豆腐套餐显示“时蔬豆腐餐 · 可配面条”“配面套餐 · 主食待选”，配料和示意图也标注未选状态。用户实际选择面食后才显示“配面条”和“面条（小麦制品）”，金额与所选规格一致。已选米饭或不含主食时不会自动改成面条。

原始10份材料保持不变。R02/R16的排名与展示顺序随本次用户要求修订，独立存放于fixtures/recommendation-policy-v2.json；原计分、价格、排除及其他预期保留。新增11项规则测试，全量133项通过。核心浏览器原“包含面食”的旧文案断言改为“已选配面条”，明确检查真实选择状态。

15项面条浏览器检查覆盖“想吃面条”“今天想吃面条不吃鸡肉”“想吃面条，不吃鸡肉”、跳过、未匹配反馈、显式替代、规格与金额、不可配送、恢复跳过及四种宽度。AI返回采用受控响应，真实执行推荐、状态和页面流程，不计新增真实模型语义验收。本轮无新增付费调用。证据见validation/round8各报告。
