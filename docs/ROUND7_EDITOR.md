# 0.7.0 要求调整弹窗

推荐页不再展示“说说这餐有什么变化”大输入框；“调整本餐要求”入口放在小A已有要求下，餐食卡片成为推荐区的主要内容。

弹窗提供“用一句话调整”和手动表单，共用同一份草稿。用户可先描述“这餐偏好面食，不吃鸡肉”，检查自动勾选的内容，再手动修改。界面明确支持主食、口味、份量和忌口，暂不支持按菜名找套餐。

“本次将修改”对比当前已生效要求，列出本餐、长期、历史倾向和临时例外的变动。只有“应用修改”写入实时状态并更新推荐，整次修改可一次撤销。取消、关闭和Esc均丢弃草稿。解除已有排除、硬约束变更及临时例外，在应用时重新要求确认。

编辑草稿复用现有状态规划器，在内存中独立保存。AI请求使用草稿上下文；手动修改后丢弃旧AI结果，关闭面板会中止请求。最终提交同时校验用户、任务和要求版本，防止旧草稿覆盖新状态。自然语言中的确认只用于预览，不能绕过最终实时状态的确认检查。

历史备注整理移入“核对历史”面板，保留来源、缓存、待确认建议和归属纠正能力。

验证包括新增6项程序测试、完整122项测试，以及草稿组合、范围切换、二次确认、取消/Esc、旧AI响应、未配置恢复、历史整理和360/390/768/1440宽度的浏览器操作。核心下单、加菜、订单费用及跨来源访问码流程独立回归。证据为validation/round7*.json；本轮无新增付费模型请求，模型提示和语义契约未变。

本次修改调整入口与编辑流程；菜名正向检索、面条与配面套餐的意图区分及跳过规则仍需后续开发，未将其计为本轮完成。

本版现已发布到原GitHub体验链接，Render同步到0.7.0。公开页面8项检查通过；一次请求失败后重试成功会刷新服务状态提示。本轮未新增付费模型调用。
