# 数据契约与预期结果读取约定

## 1. 格式与单位

JSON采用UTF-8，版本号1.0.0；ID为稳定字符串，不使用展示名称连接数据。金额统一为人民币分的非负整数，展示时除以100。配送时间为分钟。`null`表示未知或未配置，不等同于false或0。

这是依据主方案第6个保存版本制作的数据附件。下列默认值用于本数据包复现，不表示真实商家或用户事实。运行中的需求变化必须先按产品确认规则生效，再传入计算器；场景覆盖参数不能作为绕过确认的用户接口。

## 2. 核心对象

| 对象 | 核心字段及含义 |
| --- | --- |
| merchant | id、name、open；delivery按address_id给出available、fee_fen、eta_minutes |
| product | id、merchant_id、kind(main/addon)、canonical_main_dish_ids、available、packaging_fee_fen_per_unit、spec_groups、default_selections、configurations、image |
| spec_group | id、required、option_ids；组内选项互斥，本数据集每项商品最多一个规格组 |
| configuration | id在商品内唯一；option_values是完整规格组合；price_fen为该配置完整商品价；ingredients和attributes也是该配置最终事实，不是相对增量 |
| user | long_term、historical_soft_preferences、history_record_ids；全部标记demo_assumptions |
| history | user_id、day_offset、meal、order_status、belongs_to_user、consumed_confirmed、items、note |
| cart_line | product_id、configuration_id、quantity正整数、role(main/addon)；configuration_id为null表示未选齐，不能结算 |

`canonical_main_dish_ids`用于跨商家同菜与多主菜检查，不能用商品ID或主食名称代替。角色为addon的主餐商品仍具有主菜标识，仍接受重复检查。饮品和纯配菜为空数组。

`default_selections`表示可在卡片展示的预填：P01常规、P05微辣、S06带香菜。默认值如违反明确约束，不予预填。用户明确选择与默认值不同；明确选择不合格时提示冲突，不能自动换成其他配置。P09没有默认主食，比较配置不自动写入购物车选择。

配置价格均为完整值，例如P09的2200表示面食商品价22元，不是加价22元。推荐总价再加包装和配送。未选规格以合格配置内先比较偏好、再比较总价的结果作为比较配置；不能只取最低商品价。

## 3. 属性和计分

| 维度 | 本数据集值 | 匹配口径 |
| --- | --- | --- |
| spiciness | none、mild | 精确匹配，none是不辣 |
| cuisine | home、sichuan、noodles、japanese | 示例分类；主菜不会额外计分 |
| oil | low、regular、none、null | 偏好low时low或none匹配；null不匹配 |
| fried | true、false、null | 偏好非油炸匹配false；null不匹配 |
| staple | rice、noodle、none；偏好可用any | any匹配rice/noodle；none无主食不匹配any |
| portion | regular、small、large | 精确匹配，本数据有regular和small实际配置 |

软偏好为“维度→可接受值数组”，同维度多个可接受值按或关系，最多1分。先取本餐、长期、历史中的最高有效来源，未匹配不能回退到低优先来源。硬约束占用的维度不再软加分。得分数组按[本餐,长期,历史]依次降序，再按比较总价、配送时间、product_id、configuration_id升序。

显式食材词表见mock-data.json。排除`chicken`判断所有含鸡肉配置，排除`peanut`判断花生。成分已按配置展开，不能靠菜名猜测。`ingredient_information_complete=false`且存在有效食材排除时，该配置不合格；没有相关排除时可以保留但显示未知。`oil=null`仅表示油量未知，不自动意味着含某种食材。

## 4. 历史与任务日期

记录以相对日期保存；day_offset=-1是演示日期前一天。餐次顺序breakfast、lunch、dinner，当前默认lunch。恢复示例时重新锚定，刷新同一次任务不改变锚点。

有效个人记录要求属于本人，且未取消或失败；已完成订单作为购买推断，已确认吃过的记录作为明确用餐事实。同一记录的购买与用餐标识只计算一次。“上一餐”取当前餐之前最新日期与餐次的所有有效主菜；“昨天同餐”取对应日期餐次的所有有效主菜。

订单submitted本身不算已吃；用户后续明确确认吃过属于另一事件。数据包没有自动让模拟订单变成completed或consumed。缺少对应历史时要求确认继续范围，不能声称已完整核查重复。

## 5. 场景参数

每条推荐用例从原始数据的干净副本开始；不同用例不能串联污染。`setup.user_id`和`address_id`选用户与地址，`scene`描述用例生效后的条件或演示开关。

| scene字段 | 作用 |
| --- | --- |
| current_soft | 已生效的本餐软偏好 |
| current_excluded | 已生效的本餐排除食材，与长期排除合并 |
| current_hard | 已确认可生效的硬属性约束；不负责执行冲突确认流程 |
| replace_long_excluded | 用例初始长期排除集合替换，不能当成未经确认的用户输入 |
| confirmed_temporary_exceptions | 已明确确认的本餐例外，只豁免对应长期排除，不清除独立本餐排除 |
| repeat_rule | 用例有效重复规则allow/yesterday_same_meal/previous_meal |
| history_ids | 用例指定的历史集合，空数组用于缺历史场景 |
| allow_incomplete_history | 用户已经明确同意仅按现有记录继续 |
| selected_options | 以product_id为键，完整替换该商品预填选项；空对象表示没有选择；有值视为用户明确选择 |
| unavailable_products | 用于售罄演示的商品ID集合 |
| delivery_fee_overrides | 以merchant_id为键覆盖当前地址配送费，用于费用变化测试 |
| skipped_products | 本餐已跳过的商品ID，不能自动扩展为所有同主菜商品 |
| order_note | 用例备注，不能改变实际配置中的食材 |

默认配置仅在未被明确指定时使用。当前参考计算器为有限数据集服务，不是支持任意规格组合的生产推荐引擎；未来扩展多规格组时，需要验证默认值部分失效的具体处理。

## 6. 费用与购物车

商品小计为各行配置商品价乘数量；包装费为各行每件包装费乘数量；同一商家配送费每单一次；优惠为0；总价等于商品小计＋包装费＋配送费。本数据集没有起送门槛。缺失价格是数据错误，不能按0元处理。

购物车行以角色、商品、配置分别保存。主餐重复入口操作不增加数量；加菜相同商品配置可在加菜角色内合并数量。主餐与主动另加的一份相同商品不能丢失角色关系，否则换主餐会误删加菜。

购物车错误优先级：空车→跨店→历史范围尚未确认→不可售／不可配送→规格缺失→食材冲突／未知→硬属性冲突→重复。多个问题同时存在时，产品可展示全部问题；本预期的error_code断言首个阻断原因。无效车不提供可支付总额，`amounts_fen=null`不等于0元。

## 7. 推荐结果与预期断言

`ranked_product_ids`为完整稳定顺序，`display_product_ids`为主推及最多两个备选。优先展示主菜集合不重叠的候选，数量不足再按原顺序补足。完整排序与展示顺序因此可能不同。

`configuration_ids`、`totals_fen`、`scores`和`primary_exclusion_codes`只列出该场景要精确断言的关键对象，未列出的字段不表示无需计算。R01给出全部合格商品的费用和分数。

| 代码／状态 | 含义 |
| --- | --- |
| ready | 存在合格推荐 |
| no_match | 无合格推荐 |
| needs_history_confirmation | 尚缺重复判断范围确认，暂不生成声称符合该规则的推荐 |
| HISTORY_INCOMPLETE | 已同意按现有记录继续，结果仍需显示记录不足 |
| UNAVAILABLE | 商品不可售或商家未营业 |
| UNDELIVERABLE | 当前地址不配送 |
| EXCLUDED_INGREDIENT | 已知含有效排除食材 |
| UNKNOWN_INGREDIENTS | 存在食材排除但相关成分无法核实 |
| HARD_ATTRIBUTE | 与不辣等明确属性约束冲突 |
| REPEAT | 命中有效历史主菜 |
| SKIPPED | 本餐跳过商品 |
| NO_CONFIGURATION | 所指定选项不能形成有效配置 |
| EMPTY_CART | 购物车为空 |
| CROSS_MERCHANT | 跨店购物车 |
| MISSING_SPEC | 必选规格未完成 |
| NEEDS_HISTORY_CONFIRMATION | 购物车检查仍缺历史范围确认 |

推荐配置失败时依次优先报告已知食材冲突、未知食材、硬属性冲突、重复；供给问题优先于配置检查。这只是本数据包的首要原因归类约定，完整解释可保留多个原因。

## 8. 验证与未覆盖边界

verify_fixtures.py检查数据规模、ID与规格引用、字段枚举、主菜重复、需求来源计分、配置选择、费用及预期排序。它只读取已生效条件，不模拟自然语言理解、确认对话、浏览器持久化、并发请求或真实订单接口。

interaction-cases.json由实际产品执行后填写通过结果；ai-semantic-cases.json由真实模型调用后判断语义。预期语义字段是测试表达，不强制未来接口沿用相同字段名。不要根据预期文件硬编码用户说法或推荐结果来冒充AI能力。
